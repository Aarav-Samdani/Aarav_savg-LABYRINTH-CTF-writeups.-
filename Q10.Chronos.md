# Chronos

The challenge gives us a file called `capture.sal` and an Arduino sketch, `challenge.ino`, which stores a secret by encrypting it and writing it to an external I2C EEPROM.

## Reading the capture

Opening `capture.sal` in Saleae Logic 2 shows activity on two channels. Channel 1 is a steady square wave, so it should be the SCL. Channel 0 changes between clock edges, so it should be the data line.

Adding the built-in I2C analyzer (SDA = Channel 0, SCL = Channel 1) decodes 34 write transactions to I2C address `0x50`, each in the form `address, data`:

```text
0x00 = 0x00
0x01 = 0x20              
0x02–0x21 = ciphertext :
4b 0d 83 da a4 c2 9b e7 88 26 23 c3 be b0 ae 5f
eb 3d df dc 71 bc 4b f6 ce d1 c4 16 54 7a 94 19
```

## What the sketch does

The sketch generates an AES key, encrypts a secret string with it, and then writes the result to the EEPROM. The security of this entire system depends solely on the key being unguessable, because the ciphertext can be decrypted by anyone using the key.

The key is generated here in the code:

```c
void generateAesKey() {
  srand(time(0));
  for (int i = 0; i < 16; i++) {
    aesKey[i] = (byte)(rand() % 256);
  }
}
```

What function `rand()` does is, it produces pseudo-random numbers using a predetermined formula but it isn't really "random", it just looks random if we don't know the starting point. `srand(seed)` is that starting point. Calling `srand()` with the same seed twice makes `rand()` produce the same numbers both times. The only reason this seems random is that the seed, `time(0)` or the current time, on this code alone, is different every run.

## The key idea: `time(0)` on an Arduino Uno chip

A device usually knows the current time because of having an inbuilt RTC chip, which keeps time independently even when powered off. An Arduino Uno has no RTC and no other source wired in this sketch. Under avr-libc, `time(0)` stays fixed at `0` unless the program calls `set_system_time()`, which this never happens in the code.

So, basically `srand(time(0))` is really `srand(0)`. Since the seed is always `0`, `rand()` produces the exact same numbers every time. The AES key that looks random is actually fixed. It doesn't need to be cracked as we can regenerate it by running the same generation logic again.

## Changes made to the sketch

The original file already has the decryption logic inside `readAndDecrypt()`, but the actual decrypt call is commented out, and the function reads the cipher from a real EEPROM over I2C, but we don't have that hardware, so we need something that can be run directly and produce the flag:

1. **We need to add a new array, `Cipher[32]`**, to hold the 32 ciphertext bytes read from the Logic capture.
2. **Inside `readAndDecrypt()`, we need to replace the EEPROM read calls with a direct copy from `Cipher`.** The original code read the cipher bytes from a real chip; since there's no chip here, the length is set to `32` (known from the capture) and we copy the bytes from the array.
3. **Uncommented the `aesLib.decrypt(...)` line.** It was already written in the original file, we just turned it on.
4. **In `setup()`, removed the three lines that re-encrypt the word `"secret"` and write it to EEPROM**, since that would overwrite the real deciphered data and isn't needed. In their place, two lines print the AES key, and a third calls `readAndDecrypt()` and prints its result.

Everything else in the file, every other function and variable, is unchanged from the original.

## New code

```c
#include <Wire.h>
#include <AESLib.h>
#include <time.h>

#define EEPROM_I2C_ADDR 0x50
#define EEPROM_PAGE_DELAY_MS 5

AESLib aesLib;

byte aesKey[16];
byte aesIvSeed[16] = {0};

byte Cipher[32] = {
  0x4b,0x0d,0x83,0xda,0xa4,0xc2,0x9b,0xe7,0x88,0x26,0x23,0xc3,0xbe,0xb0,0xae,0x5f,
  0xeb,0x3d,0xdf,0xdc,0x71,0xbc,0x4b,0xf6,0xce,0xd1,0xc4,0x16,0x54,0x7a,0x94,0x19
};

void eepromWriteByte(unsigned int addr, byte data) {
  Wire.beginTransmission(EEPROM_I2C_ADDR);
  Wire.write((int)(addr >> 8));
  Wire.write((int)(addr & 0xFF));
  Wire.write(data);
  Wire.endTransmission();
  delay(EEPROM_PAGE_DELAY_MS);
}
byte eepromReadByte(unsigned int addr) {
  Wire.beginTransmission(EEPROM_I2C_ADDR);
  Wire.write((int)(addr >> 8));
  Wire.write((int)(addr & 0xFF));
  Wire.endTransmission();
  Wire.requestFrom(EEPROM_I2C_ADDR, 1);
  if (Wire.available()) {
    return Wire.read();
  }
  return 0xFF;
}
void eepromWriteBlock(unsigned int addr, const byte* data, int len) {
  for (int i = 0; i < len; i++) {
    eepromWriteByte(addr + i, data[i]);
  }
}
void eepromReadBlock(unsigned int addr, byte* buffer, int len) {
  for (int i = 0; i < len; i++) {
    buffer[i] = eepromReadByte(addr + i);
  }
}
void generateAesKey() {
  srand(time(0));
  for (int i = 0; i < 16; i++) {
    aesKey[i] = (byte)(rand() % 256);
  }
}
void encryptAndStore(const String &plainText, unsigned int eepromAddr) {
  int rawLen = plainText.length() + 1;
  int paddedLen = ((rawLen / 16) + 1) * 16;

  byte plainBuf[paddedLen];
  memset(plainBuf, 0, paddedLen);
  plainText.getBytes(plainBuf, rawLen);

  byte cipherBuf[paddedLen];
  byte iv[16];
  memcpy(iv, aesIvSeed, 16);
  aesLib.encrypt(plainBuf, paddedLen, cipherBuf, aesKey, 128, iv);

  byte lenBytes[2] = { (byte)(paddedLen >> 8), (byte)(paddedLen & 0xFF) };
  eepromWriteBlock(eepromAddr, lenBytes, 2);
  eepromWriteBlock(eepromAddr + 2, cipherBuf, paddedLen);

  Serial.print("Stored encrypted string, ciphertext length: ");
  Serial.println(paddedLen);
}
String readAndDecrypt(unsigned int eepromAddr) {
  int paddedLen = 32;
  byte cipherBuf[32];
  memcpy(cipherBuf, Cipher, 32);

  byte plainBuf[paddedLen];
  byte iv[16];
  memcpy(iv, aesIvSeed, 16);

  aesLib.decrypt(cipherBuf, paddedLen, plainBuf, aesKey, 128, iv);
  plainBuf[paddedLen - 1] = '\0';
  return String((char*)plainBuf);
}
void setup() {
  Serial.begin(9600);
  delay(1000);
  Wire.begin();

  generateAesKey();

  Serial.print("key = ");
  for (int i = 0; i < 16; i++) {
    Serial.print(aesKey[i], HEX);
    Serial.print(" ");
  }
  Serial.println();

  unsigned int storageAddr = 0;
  Serial.println(readAndDecrypt(storageAddr));
}

void loop() {
}
```

Running this in the Wokwi simulator (online arduino simulator) prints:

```text
key = 42 FB 9F E0 59 81 5A 81 66 A1 0E 5C 4E B4 DA EC
chr0n0s_st4rt3d_t1m3_fr0m_0!
```

The key is the same every run, proving our claim that `time(0)` always returns as `0` on this hardware.
